# Revision 2 — 23 October 2026

News collection can now retain the stable baseline while prioritizing current
portfolio/research identities and rotating through a bounded source-validated
sample. This revision changes collection scope and evidence. It does not change
scoring, model weights, investment thresholds, release gates or broker orders.

## Collection behavior

| Area | Behavior |
| --- | --- |
| Scope | At most 60 unique symbol analyses per batch. This is not an HTTP-request cap: each configured source and its retries can add requests. The selected set is not full-market news coverage. |
| Priority | Source-validated portfolio/research identities, then the stable env/default baseline. Remaining room rotates through eligible identities and uses a broader market sample when room remains. Membership is context, not proof of a positive holding or executable eligibility. |
| Identity | Join exact venue-qualified symbols to source names. Missing, malformed or conflicting identities remain explicit; adaptive collection does not guess a company name. Unknown public symbols are reported in a bounded global list without a portfolio-role association. |
| Precedence | An explicit CLI universe is absolute and does not require source discovery. With adaptive mode off, env/default selection retains its prior behavior. Adaptive mode treats that list as the stable baseline. Oversized lists are capped and omissions are reported. |
| Schedule | Collections run at 17:00 and 23:00 Asia/Riyadh. The archive uses a daily `(Riyadh date, symbol)` key. A second collection may produce fresh evidence without replacing an earlier row for that symbol. |
| Adoption run | A main-branch push affecting the news engine, collector or its workflow runs the same collector. The workflow remains path scoped. One shared concurrency group serializes this workflow's writers across all refs, including manual branch runs. |
| Time limits | News analysis is bounded to 600 seconds per batch; the workflow has a separate 20-minute outer limit. The batch timeout does not bound preceding Google source reads. |
| Dry run | Read-only source discovery may authenticate and read the exact workbook, but dry runs do not create, format or append the archive. |

## Acquisition and point-in-time evidence

Evidence separates source publication timestamps, identity-read timestamps,
article publication/crawl timestamps and collection timestamps. Cached results
retain their original acquisition evidence and cache flag. The archive's
`Collected UTC` is its write timestamp; use the evidence artifact to verify the
original acquisition time. A 72-hour source-publication recency test concerns
identity discovery metadata. It is not a quote-freshness or article-recency test.
Identity reads are bounded windows under the existing contiguous canonical
writer contract. Spare allocated grid rows do not imply populated truncation;
a populated capped boundary remains incomplete. The recorded ranges are not
a full allocated-grid or sparse late-row audit.

Complete `OK` and legitimate `EMPTY` acquisitions can enter the daily archive.
`PARTIAL`, `ERROR`, `UNAVAILABLE` and `UNKNOWN` acquisitions remain visible and
retryable rather than being written as neutral daily samples. Missing source
reads or identities keep discovery incomplete even when the selected news
acquisitions succeed. Evidence reports selected acquisition completeness and
discovery completeness separately. It preserves bounded public article metadata
without quantities, cash, orders, raw provider exceptions or feed credentials.

Archive keys require a successful read and the expected row-5 header. A failed,
empty or malformed header read withholds append rather than proving an empty
archive; a valid header with no data rows is a legitimate empty archive.
Blank header padding is tolerated, while additional nonblank columns remain
unverified. Reads may retry. A non-idempotent append is attempted once: a
timeout can occur after Google committed it, so an ambiguous result remains
`UNKNOWN` and the next invocation must re-read daily keys before retrying.
`APPEND_ACCEPTED` records a successful API response, not independent readback
certification. These safeguards do not promise atomic exactly-once writes
against external or cross-workflow writers and do not rewrite old duplicates.
The artifact retains acquisition, discovery and archive-write results separately.
A bounded stdout summary exposes their counts, cap and safe error codes without
identity names, symbol lists or financial positions, allowing live verification
without downloading the full artifact.

## Validation and adoption

Independent prepublication verification passed 121 focused Python news tests
covering adaptive selection, acquisition, existing contracts and single-flight
cancellation.
The adaptive regression suite is enrolled in the blocking lean CI lane.

The final integration on merged revision 1, including the news suites, required-CI,
runner-pin, workflow-flag and native-chain contracts, passed 155 tests with three
optional runner baseline comparisons skipped because their baseline directory
was not supplied. The native GAS harness separately passed 28/28 checks,
including the revision-1 timezone correction. The CI edit adds only
the adaptive suite to the existing blocking list.

The tests exercise bounded workloads, exact-symbol/name joins, explicit CLI
precedence, unknown/conflicting identities, publication changes, malformed
receipts, partial research rows, failure/empty distinctions, retry recovery,
collection deadlines and dry-run write isolation. Independent review corrected
silent missing identities, a timestamp year mistaken for a source run, and CLI
discovery requirements. Follow-up regressions cover spare allocated grids,
global unknown-identity diagnostics, unreadable or malformed archive headers,
valid empty archives, pre/post-commit append errors, next-invocation recovery,
header padding and bounded evidence summaries.

A successful live collection and its evidence artifact are still pending.
Adoption requires passing CI on the exact published commit and checking that
the resulting run respects the budget, scope, acquisition statuses and archive
grain. Collection success alone is not prediction accuracy, learned improvement
or investment recommendation readiness. Automatic production learning remains
outside this revision.
