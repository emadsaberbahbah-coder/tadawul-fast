# Revision 1 — 23 October 2026

This revision addresses verified operational and evidence defects. It does not
change financial thresholds, release gates, scoring weights or broker orders.

## Before and after

| Area | Before | Revised behavior |
| --- | --- | --- |
| Cache retention | Expired untouched quote/page payloads remained until lookup or capacity eviction | Traffic periodically reclaims expired payloads under the existing async lock; live TTL/value/LRU behavior is preserved |
| GAS decision chain | A nonthrowing render could permanently complete a source cohort without proving consumption | Completion requires a readable before/after native status, a new current-attempt timestamp and one exact verified source-run receipt; unproven attempts remain retryable |
| News acquisition | Fetch failures could become neutral daily records and block recovery | Complete OK/EMPTY observations alone enter the daily archive/cache; partial, failed, unsupported and unknown observations remain explicit and retryable |
| News evidence | The aggregate archive lacked bounded article provenance | Each workflow retains per-symbol acquisition status and up to five public article links with publisher/publication/collection metadata in an artifact |
| News presentation | Failed collection could say no recent headlines | Unavailable and incomplete collections are labeled explicitly |
| Sector join | The optional join read Asset Class as Sector | The existing default-off join resolves Symbol/Sector headers explicitly |

## Validation before publication

- Production requirements installed into an isolated local Python 3.12 environment.
- Final focused regression run: 265 passed, covering cache, native chain,
  news acquisition/contracts/cancellation, version pins, existing learning
  metrics, data engine, scoring, learning guards and required CI verdict.
- Separate unchanged release/freshness/final-publication regression run:
  371 passed and 10 intentionally skipped.
- Native GAS chain harness: 24/24 passed; five versioned GAS sources compile.
- Independent reviews reproduced and corrected unreadable-baseline chain
  completion, partial-news archival and unsupported-feed false-empty cases.
- Regression sensitivity: original cache fails four of five retention tests;
  original chain fails the new withheld-receipt completion case.
- Synthetic cache fixture: 5,000 expired 8 KB payloads, followed by one write,
  retained 5,001 entries before and one after; approximately 42.83 MB tracked
  allocations released. This is not a prediction of whole-process RSS savings.
- New regressions are enrolled in the blocking CI lane. CI must pass on the
  exact published commit before production deployment.

## Acceptance and remaining work

Backend adoption requires a live Render deployment at the reviewed commit,
HTTP health/readiness checks, and absence of new runtime failures. GAS source
publication requires authorized access to the bound project and separate
installed-version/trigger verification. A GitHub merge does not install GAS.

Current source/decision receipt disagreement must be resolved by refreshing
the correct source cohort and verifying readback. Never rewrite counters,
receipts, cash or performance history merely to make a gate pass. The chain
remains default off until installation and its operating configuration are
verified. Existing S-1 NOT_DECIDABLE and feed WITHHELD remain valid outcomes.

News universe expansion, company-name joins, market-event attribution and
clean out-of-sample learning promotion remain subsequent bounded work. The
existing direction-aware performance summaries predate this revision. No
automatic production learning weights are enabled here.

## Rollback

Revert this revision and deploy the preceding known-good backend commit if
postdeploy functional checks regress. GAS can revert only its changed chain
source independently. No schema migration or financial history rewrite is
required. Keep news evidence artifacts for incident analysis.
