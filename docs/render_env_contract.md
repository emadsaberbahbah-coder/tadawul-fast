# Render ENV contract

Generated by `python scripts/render_env_contract.py` (render_env_contract 1.0.0). Do not edit by hand: regenerate and commit. `python scripts/render_env_contract.py --check` exits 1 when this file is stale.

Build Spec item H-8. This is a static contract read from the source code by AST. It is not a readback of the live Render service. It lists the ENV names the web service reads and their code defaults, never a secret value.

Rules:

- Names and code defaults only. A default shown as `-` could not be evaluated statically and is not guessed.
- Owner decision D7 (public repository) is open, so names that carry or switch authentication, tokens or other secrets are left out of this document. No name in sections A-C was withheld by this rule.
- Render takes ENV from two places: the service's own Environment list and every linked Environment Group (Procfile names the group `tfb-server`). When this contract says a key must be unset, check both.
- expected production value: not recorded. `config/render_env_expected.json` is absent; every row says `not recorded` until the owner fills that file.

## A. Platform keys outside the TFB_ prefix

### Why TFB_APP_VERSION and APP_VERSION MUST be unset

`app_version` on /health is not a code constant. config.py reads TFB_APP_VERSION, then APP_VERSION, and the first one set wins. Only when both are unset does main.py fall back to its APP_ENTRY_VERSION, so /health then reports app_version equal to entry_version. On 13 Oct 2026 the owner's /health showed app_version 5.111.0 while entry_version was 8.14.3. The literal 5.111.0 is not in main.py, config.py, env.py or core/config.py, so one of the two keys is still set in the service ENV or in a linked env group (`tfb-server`). Delete it in both places. Read-back: GET /health shows app_version equal to entry_version.

## Refreshing this contract

- After changing any input (main.py gate tables, the decision modules' ENV readers, surface_gate_states, verify_deployment FLAGS or `config/render_env_expected.json`), run `python scripts/render_env_contract.py` and commit the result.
- `config/render_env_expected.json` is owner-filled: `{"recorded": "YYYY-MM-DD", "expected": {"NAME": "value"}}`. Plain values only; the generator withholds anything that does not look like a plain flag value, and names covered by D7 are never printed. The word `unset` records a key that must stay unset.
