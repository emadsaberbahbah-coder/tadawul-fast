# Commit Sheet: the sync-render handshake (await_cockpit_receipts 1.1.0, daily_sync 1.0.9, decision_surface_freshness 1.1.0, release_decision_feed workflow 1.3.0), 2026-11-02

**Scope.** Owner, 2 Nov 2026: "the system costs a lot ... improve today, results tomorrow"; readiness brief: "final decision after sources settle, bounded recovery tied to source progress". Every production sync (`daily_sync.yml`, scheduled ~10:26 / 17:16-17:57 / 23:27 Riyadh as delivered) ends with three timing-only red runs even when the data is good. This PR adds three gated items, every gate default OFF, so with the Variables unset every workflow behaves exactly as before (the YAML differs only by skipped steps, a timeout and an artifact path; no audit judgement, threshold or veto moves; `--publish-blockers` and every fail-closed veto stay exactly as they are). Read-only for the workbook: nothing here writes a cell, places an order, forces a selection or raises an executable count. The work is reviewed on `main` through the existing deployment authorization; nothing is deployed to Render and no workflow is dispatched by this change.

## Post-merge order (owner; one ENV arming per evidence run)
1. Set the repository Variable `TFB_SYNC_AWAIT_RENDER=1` for ONE scheduled sync. Evidence: the final job's step summary line "Await render (handshake): consumed after N s ..." and `await_render.json` in `final-decision-publication-<run>`; the final audit, `decision_surface_freshness` and the after-sync release all green on a healthy sync. Leave `TFB_SYNC_AWAIT_RENDER_MIN` unset (15) unless the render takes longer; the cap is 20.
2. Then set `TFB_RELEASE_DEFER_DURING_SYNC=1`. Evidence: a scheduled slot that lands inside a sync ends green with `deferred=true` in its summary table and `release-decision-feed-<run>`; a slot outside a sync runs the release step as before. With the sticky kill armed, every slot still runs the release step (`defer_reason=sticky_kill_armed` in the step outputs; the kill lands).
3. Rollback at any time: unset the Variable; the step is skipped on the next run.

Caveats: with the handshake armed, the sync's final job holds the production write lease for up to 15 minutes longer (a queued recovery or a scheduled release slot waits or defers behind it); the job timeouts rose to 55 (sync final job) and 45 (freshness) minutes to carry the cap and the step's 25-minute backstop; `actions: read` was already granted to the release workflow, so no permission changed.
