## Fixed in this branch

### F1 (HIGH, #723): research pass ignores diversification caps
- **Where:** `core/analysis/opportunity_builder.py`, `_select_and_size`,
  research branch. A research pick was appended before `sector_counts`,
  `market_counts` or `funded_issuers` advanced, so the cap checks above it
  never fired in research.
- **Effect:** the cockpit's stability core builds the final board from that
  list, so the board could be all one sector. The allocate replay then
  re-applies `max_per_sector` and defers the over-cap seats, which still hold
  board slots. Cash is left unallocated.
- **Reproduced:** 4 Energy and 2 Materials names, `max_selected=4`,
  `max_per_sector=2`, 100,000 SAR.

  | Flow | Board | Funded | Total |
  |---|---|---|---|
  | v1.23 single pass | - | E0, E1, M0, M1 | 100,000 SAR |
  | v1.24.1 two-pass | E0..E3 | E0, E1 | 50,000 SAR |
  | v1.24.2, gate ON | E0, E1, M0, M1 | E0, E1, M0, M1 | 100,000 SAR |

  With the gate ON, the funded list is identical to the single pass.
- **Fix (v1.24.2, gated, default OFF):** with `TFB_OPP_RESEARCH_DIVERSIFY=1`,
  a research pick advances the sector, market and issuer counters exactly as
  a funded pick does. Cash and sizing ledgers are untouched in research.
  - The env name falls under the `TFB_OPP_` policy prefix, so it is bound
    into the signed replay fingerprint. The existing source-guard test
    passes, and the harness asserts the binding.
  - Changing the variable mid-refresh rejects the replay. It fails closed
    and allocates nothing.
- **Gate OFF:** byte-identical v1.24.1. Ordinary single-pass requests are
  unaffected in both modes, and the harness asserts this.
- **Version pin:** `scripts/verify_deployment.py` is moved to 1.24.2. The
  Apps Script compares the snapshot's builder version with the same
  response's version, not a literal, so the bump does not withhold funding.
- **Harness:** `tests/test_ob_research_diversify.py` passes 10/10.
  - Golden negative against the base builder (`TFB_ORD_BUILDER=<base copy>`):
    5/10. All 5 gate-ON cases fail and all 5 gate-OFF cases pass.

### F2 (MEDIUM-HIGH, #722): successfully priced rows counted as INVALID
- **Where:** `core/data_validity.py`, `_INVALID_WARNINGS`. The pattern was
  unanchored, so `identity_quarantined` matched inside the engine tag
  `fund_identity_quarantined`.
- **What that tag means:** the AW-2 guard stripped display identity from the
  EODHD fundamentals side channel. It is a fundamentals-only fact, not a price
  failure.
- **Effect:** a Yahoo-priced row with that tag was classed INVALID. This
  under-counts acquisition coverage on the sync stamp and in the full-refresh
  and decision-surface audits.
- **Fix (data_validity v1.0.1):** a `(?<![a-z0-9_])` lookbehind, so a failure
  tag must start a token.
  - Every real failure tag in core, scripts and routes already starts a token
    (`identity_quarantined:...`, `fetch_failed:...`).
  - `fund_identity_quarantined` was the only colliding warning tag. The other
    substring hits were function names.
- **Not env-gated, deliberately:** this is a same-day defect with no safe
  use, and the change can only move a row from INVALID to its true state.
  The owner should confirm this exception.
- **Harness:** `tests/test_data_validity_token_anchor.py` passes 8/8. Every
  failure token is still INVALID in 7 textual positions and in the `error`
  field.
  - Golden negative against the base module: 3/8. The fund_identity cases
    fail, and all real-failure cases still pass, which proves nothing was
    loosened.

### F3 (HIGH if any .L holding exists, #727): pence quote passes a pounds ledger
- **Where:** `scripts/run_dashboard_sync.py`, `_portfolio_holdings_contract`.
  Both currencies are upper-cased before comparison. The engine quotes `.L`
  in pence as `GBp`, and the ledger reader only admits a 3-letter major code.
  `GBp` upper-cases to `GBP`, so it passes.
- **Effect:** Position Value and Unrealized P/L publish 100x. The #727 commit
  sheet says the currency check prevents exactly this.
- **Not a regression:** base had the same maths and no check at all.
- **Reproduced:** VOD.L, 100 shares at 25.00 GBP, quote 2600 GBp.
  Position Value 260,000 (true value 2,600), P/L 257,500, P/L% 10,300.
- **Fix (v6.64.8, gated, default OFF):** with `TFB_PF_MINOR_UNIT_CCY_GUARD=1`,
  a raw minor-unit quote currency (GBp, GBX, GBx, ZAc, ZAC, ILA, ILa) is
  rejected. The existing fail-closed path then keeps the prior portfolio
  page. Gate OFF is byte-identical v6.64.7. The verify_deployment pin is
  moved to 6.64.8.
- **Harness:** `tests/test_pf_minor_unit_ccy_guard.py` passes 6/6.
  - Golden negative against the base script: 4/6. The pence-vs-pounds case
    and the version floor fail.
  - The other minor-unit spellings were already rejected on base, because
    they upper-case to a code that differs from the ledger's. So `GBp` was
    the one real hole.
- **Arming note:** with the guard ON, a .L holding blocks the whole
  portfolio refresh until the ledger and quote units agree. That is safer
  than publishing 100x numbers, but it is an operator decision.

## Found, not fixed here (owner decision needed)

### N1 (MEDIUM, #722): unpriced provider patch now discarded whole
- **Where:** `core/data_engine_v2.py`, factory loop, around line 17590.
  Before the change, an unpriced patch (for example an EODHD 429 on the
  realtime quote) was fill-merged. Now it is dropped entirely when a later
  provider prices the row.
- **Effect:** EODHD fundamentals and history stats are lost. The fundamentals
  fallback refills numerics but strips name and sector, and blank sectors
  feed the sector caps. It also costs an extra EODHD call.
- **Reproduced by the reviewer:**
  - base 5.151.0: name, sector, market_cap and pe_ttm present
  - 5.151.2: all None
- **Not gated**, despite a version note saying fundamentals are unchanged.
- **Proposal:** fill-merge the non-price fields from unpriced patches, and
  exclude only price, timestamp, provider label and error. Or gate the drop.
- **Why not done here:** it changes data_engine merge semantics in a
  17k-line module and needs a provider-level regression set.

### N2 (MEDIUM, #722): `data=` stamp token changed meaning
- **Where:** `scripts/run_dashboard_sync.py`, `_status_stamp_row`. `data=` is
  now the acquisition verdict, while Status follows `policy_data`.
- **Effect:** a stamp can read `SUCCESS ... data=PARTIAL` even with
  `TFB_SYNC_STATUS_TRUTH=1`, which contradicts AT-07.
  - `tfb_acceptance.py` D10-4b will report it.
  - `send_digest.py` gates on `data=`, so the digest now depends on
    acquisition proof.
- **Proposal:** keep `data=` as the policy verdict and rely on the existing
  `acquisition=` token. Or gate the new meaning.
- **Why not done here:** it changes a published contract that three consumers
  read, and the owner must choose which meaning wins.

### N3 (MEDIUM, #723): new funding flow has no legacy fallback
- **Where:** `16_Decision_Top10.gs`. The two-pass flow is on by default. The
  only brake (`DT10_BOARD_FUNDING_MODE=research`) zeroes all allocation, and
  `DT10_P145_GRACE_SIZING_LEGACY=1` is now ignored. This is documented in
  `docs/reviews/core-board-funding-20261007.md`, but it departs from the
  default-OFF convention.
- **Proposal:** add an explicit legacy single-pass mode. It is an Apps Script
  edit, so it would be delivered as paste instructions.

### N4 (LOW-MEDIUM, #723): stability-OFF board is not capped at Max Selected
- **When:** the brake is on, or replay fails.
  `dt10ApplyStability_` returns early and the research list is unbounded.
- **Reproduced:** 40 qualified names gives 40 rendered seats against
  `max_selected` 10. Money is zero, but the board is wrong.
- **Proposal:** slice to Max Selected in the stability-OFF branch (an Apps
  Script paste).

### N5 (MEDIUM, #726): one caller's cancellation cancels other waiters
- **Where:** `core/providers/yahoo_chart_provider.py`, `SingleFlight.run`
  (owner `future.cancel()` on its own CancelledError) and
  `get_enriched_quotes_batch` (re-raises a child CancelledError).
- **Scenario:** a waiter that was never cancelled receives CancelledError
  when the owning caller times out. Its whole batch aborts, including
  symbols that had already answered. Base behaviour was a contained timeout.
- **Reproduced by the reviewer.** No wrong or stale price is published.
- **Deliberate in #726:** `test_ycp_singleflight_cancellation.py` asserts
  this propagation.
- **Proposal:** in the waiter path, catch CancelledError when
  `current_task().cancelling() == 0` and become the new owner (or return
  None). In the batch, re-raise only when the batch task itself is
  cancelling.
- **Why not done here:** it reverses a tested design choice in the live
  price provider.

### N6 (LOW, #729): cash-floor recount walks board order, not funding order
- **Where:** `apps_script/16_Decision_Top10.gs`, `dt10FinalizeCashFloor_`.
  Python walks funding order.
- **Effect:** `would_unfund_seats` and the alert count can differ from the
  backend. The SAR total matches, and no ticket or money changes.
- **Reproduced:** board order A10, B60, C60 gives 1 seat; funding order gives
  2 seats (Python also gives 2).
- **Proposal:** walk in the replay's `allocated.selected` order (an Apps
  Script paste).
