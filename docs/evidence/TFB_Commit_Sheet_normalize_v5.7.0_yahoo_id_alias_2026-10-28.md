## S2 - WHAT
- `_YAHOO_ID_ALIAS` holds the nine pairs above. It is read only when `TFB_YAHOO_ID_ALIAS=1`, at the top of `to_yahoo_symbol()`, after `normalize_symbol()`.
- **Off (default):** byte-identical to v5.6.0. EODHD and Finnhub routes never change.
- **How it travels:**
  - The engine calls the Yahoo adapter with the page symbol.
  - The adapter maps it for the actual call (`_yc_yahoo_symbol`), and its response-identity guard (YC-1) compares the response against the mapped id.
  - The adapter's patch declares the page symbol, so the engine guard (AU-1) passes, and a crossed coin is still refused (A6).
- **Targets:** every target is idempotent through `to_yahoo_symbol` (A3).
- **Restart:** cached normalization needs a process restart after arming (`lru_cache`), as with the earlier FX and crypto maps. A Render deploy or restart does that.
