## S2 — Design (WHY on the file header)
The framework's 75-check catalogue (§2.5) was measured by hand once; no script reproduced the numbers, no tab/row records (§2.2/§2.3) or DQ scores (§2.4) existed, no baseline comparison, no daily scorecard. Every later WP must print its before/after counts from one harness, so the harness is built first and wired into the only job that holds the exported bytes.
- **Read-only, standalone, deterministic.** openpyxl `read_only=True, data_only=True`; the sibling `tfb_export_audit.py` is imported LAZILY inside `_tea()` (first `from scripts import …`, then the script's own directory; `(ImportError, SystemExit)` are both caught because its import guard calls `sys.exit(2)` without openpyxl). Importing the module performs no I/O, imports no openpyxl and never exits (test P9 proves it under `python -I`). Reference clocks are export-derived — `ref_time_rows` = max `Last Updated (UTC)` (2026-10-10T18:18:33.85Z), `ref_time_log` = last parseable `_Run_Log` stamp (2026-10-10T18:35:32Z) — never the wall clock, so the digest is identical on every run.
- **One function per DQ-id** returning one Check record `{id, name, group, cls, critical, status, count, values, examples, detail, rule, fix_ref}`; status computed from `count` against the CONFIG block (`THRESHOLDS`, `POLICY`, `EXPECT`, `KNOWN_TABS` with §2.2 metadata, verbatim 115/122 header contracts, GICS-11, `SELL_CLASS`, `DECISION_CRITICAL_IDS`, `FX_BAND`, `FX_TO_SAR`, `SYNC_BUDGET_MS`, `PLACEHOLDER_DATES`, `PROGRAM_V2_START`) — no magic numbers in check bodies. Inputs absent from an export give NOT_CHECKED, never PASS. Five NOT_CHECKED records (render gate states, sharing ACL, formula ranges, weight-basis label, broker truth) and one INFO record (e-mail cells in System_Logs, count only) are always emitted: **81 records = 75 DQ + 6**.
- **Decision-critical class** = `{DQ-07, 08, 09, 10, 16, 22, 24, 25, 30, 33, 34, 38, 46, 53, 62}` with the count semantics of challenge correction #6 (e.g. DQ-16 = |misclassed ∪ name-mismatch| + ALTSYMBOL = 10; DQ-24 = margin cells |v| > 1.5 on all four pages = 795; DQ-25 = D/E > 10 without the exact tag `fund_unit_contract:yahoo:debt_to_equity` = 80; DQ-30 = rows at DQ 100 with a garbage fundamental = 360; DQ-34 = tuple-conflict rows in INVESTABLE ∪ BOARD ∪ HOLDINGS = 9; DQ-38 = INVEST-on-SELL + INVESTABLE-unpriced = 0 → PASS; DQ-46 = trailing consecutive all-BLOCK action-log runs = 3). Exit 1 only when (no baseline and a decision-critical check is FAIL) or (baseline and a decision-critical regression); 2 on usage/load errors.
- **Review fix (round 1, 2026-10-11, same v1.0.0 — the file is new in this WP and unreleased):** `BASELINE_HIGHER_IS_BETTER = {"DQ-23"}` → `set()`. The spec's baseline rule listed DQ-23 as an inverted measure on the assumption that its count is the share of rows at +3 h; the delivered `dq_23_stamp_offset` returns count = rows whose Riyadh − UTC offset is **not** +3 h (0 on 10-10), so lower is better like every other delivered count and the inverted entry made `compare_to_baseline` label a rise in bad rows an improvement (reviewer reproduction: baseline FAIL 5 → current FAIL 10 gave `improvements ['DQ-23']`; 5 → 2 gave `regressions ['DQ-23']`). Exit code and `decision_critical_regressions` were never affected (DQ-23 is not decision-critical); the `## Trend vs baseline` section and `report['baseline']` were. The fix is one constant plus a dated note above the header WHY block (the WHY block itself is untouched); test P6 now asserts 5 → 10 regresses and 5 → 2 improves (that assertion fails against the build-1 script, passes against the fix). No fixture, digest or selftest regeneration was needed: the 10-10 comparison is 0 vs 0 and the selftest cases-digest is label-based — re-verified below.
- **Corrections applied:** #1 redaction guard is whitelist-by-construction (numeric leaves only under `values / per_page / by_field / by_horizon / distribution / dq_scores / expect` or under keys ending `_count|_rows|_n|_pct|_share|_mean|_max|_min|_total|_bytes|_ms|_hours|_days|_distinct|_blank|_tagged|_untagged|_runs|_pairs|_errors` or exactly `count`; strings fail on `\d[\d,]*(\.\d+)?\s*(SAR|USD)\b` and on `\b(NAV|cash|balance|deployable|ticket|equity|P&L)\b\D{0,15}\d{4,}`); it runs on the report, the markdown and the fixture before every write and in `--selftest`. #2 `params` = {expect, asof, now, mode, baseline basename, tz_offset_hours, rows_included, examples_private}; `export` and `baseline.file` are basenames; digest excludes `generated_at, digest, export_path, runtime_ms`. #3 DQ-48 grid stops at the first blank Verdict or a Symbol containing `|` (the `route v4.18.1 | builder v1.25.0 | pool=…` footer, which also feeds the Top_10 tab record's writer_version) → 500 rows. #4 DQ-38 PASS with the INFO sub-metrics (4 INVESTABLE without ROI 12M; 18 eligible). #5 DQ-34 cohort = INVESTABLE ∪ BOARD ∪ HOLDINGS → 9 (board seat 2286.SR). #7 DQ-24 row census uses the EXACT units `pts` / `frac` (3,290 / 3,930). #9 lazy import order and `(ImportError, SystemExit)`. #10 `--baseline-out`, `audit_workbook(path, expect, asof, now_utc, baseline, mode, tz_offset, include_rows, examples_private)`, `build_synthetic(dir, clean) -> path`, `compare_to_baseline`, `_assert_redacted` raising `RedactionError`. #11 import-safety test P9 as rewritten. #12 header-row predicates (`Hypothesis ID` at row index 4, `Record ID` at row index 4, ledger header at row index 3). #13 DQ-70 vocabulary rule = more than one spelling per severity. #14 `restore_test != 'true'` on the upload step too. #15 row records are opt-in (`--rows`); `rows_summary` counts are always present; examples suppressed on DQ-17/51/53–60 unless `--examples-private`. #16 acceptance numbers re-stated below. #17 anchor text.
- **Section 2.2 tab records** (51 = 50 sheets + the `My_Investments` ghost): visibility, owner lane / writer / purpose / cadence / retention / criticality from `KNOWN_TABS`, writer_version parsed from stamps (STATUS-STAMP, Dashboard_Audit `engine=`/`registry=`, cockpit footer, `actions v`, `S-1 GATE v`, `SHADOW BOARD v`, `Writer Version` columns), contract {header_sha256, columns_n, width_n}, row baseline, live/data rows, padding rows, cells_used_total, in_registry, in_dictionary, status ∈ {ok, orphan, legacy, ghost}, last_written. **Section 2.3 row records** for the cohort INVEST ∪ INVESTABLE ∪ BOARD ∪ QUALIFIED ∪ HOLDINGS (182 on 10-10: 10 board seats, 7 holding rows, 156 investable, 9 qualified) with row_state, business_criticality, C/A/S/T shares, checks_failed, severity (170 P0 / 10 P1 / 2 none), fix_ref, evidence_ref `sha16:page!row`. **Section 2.4 DQ scores** per page × class with the C/A/S/T weights; critical (Identity, Quote, Scores, Forecast-on-cohort) and non-critical reported separately, never blended.
- **Workflow wiring (default OFF).** `backup_workbook.py` v1.5.0 adds `_write_local_copy(data, sha)` called between the min-bytes check and the dry-run return; `TFB_BACKUP_LOCAL_COPY` unset → returns before any I/O or log line (byte-identical behaviour to v1.4.0); set → 0600 file + one stderr line; any exception → `NOTE: local copy failed: …`, return code untouched. `workbook_backup.yml` v1.2.0 derives that env from the repo Variable `TFB_DQ_AUDIT_MODE` (observe/enforce → `$RUNNER_TEMP/tfb_export.xlsx`, else `''`), runs the audit in the same job with `continue-on-error` unless enforce, appends the scorecard to `$GITHUB_STEP_SUMMARY`, uploads only `dq_report.json` + `dq_scorecard.md` (actions/upload-artifact@v7, 30 days), and removes the xlsx in the always() cleanup. **The xlsx is never uploaded.**

5. **Fixture refresh (after each later WP arming):** download `dq_report.json`, or run `python scripts/tfb_workbook_dq_audit.py <export> --baseline-out tests/fixtures/dq_baseline_<date>.json`, commit the new fixture and point the workflow's `--baseline` at it.
6. **Local use:** `python scripts/tfb_workbook_dq_audit.py export.xlsx --md dq_scorecard.md --json dq_report.json --baseline tests/fixtures/dq_baseline_2026-10-10.json` (add `--rows` for the per-row cohort records, `--examples-private` for ledger/cash symbol examples — neither is used by the workflow).

**Rollback:** set `TFB_DQ_AUDIT_MODE` to off / delete the Variable (same effect as the default); or revert `.github/workflows/workbook_backup.yml` and `scripts/backup_workbook.py` to the base SHAs above and delete the three new files — nothing else depends on them.
